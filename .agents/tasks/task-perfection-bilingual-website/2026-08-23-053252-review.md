# Bilingual documentation, CI/CD fixes, TypeScript definitions, and public website

This change modernizes the ctxman project infrastructure by fixing ESLint warnings across the codebase, resolving CI/CD workflow issues, adding TypeScript type definitions for programmatic API consumers, enhancing documentation with performance benchmarks, and creating a bilingual VitePress public website. The work spans five feature areas delivered in a coordinated effort to bring the project to production-ready quality standards.

**Watch for:** The new release.yml workflow triggers on `push: tags: ['v*']` but the npm-publish.yml also retained its original `push: tags: ['v*']` trigger, creating a potential race condition where both workflows could attempt npm publishing simultaneously. The release.yml correctly creates GitHub releases which trigger npm-publish.yml via the `release: created` event, so the tag trigger in npm-publish.yml should be removed to avoid duplicate publish attempts.

**Verdict**: NEEDS_CHANGES

## High-level view

The ESLint migration to flat config is complete and all 191 no-unused-vars warnings were resolved by adding ignore patterns for underscore-prefixed variables. This is a pragmatic solution that maintains code quality while acknowledging intentional unused parameters in callbacks and event handlers.

CI/CD workflows were restructured with proper job dependencies, timeouts, and concurrency groups. Security audit and CodeQL jobs were added to the main CI pipeline. The release workflow was added but overlaps with npm-publish triggers.

TypeScript definitions cover all 17 exported classes and functions with proper documentation. The definitions are comprehensive and will enable better IDE support for consumers using the programmatic API.

Documentation was enhanced with PERFORMANCE.md and PERFORMANCE-tr.md providing benchmarks for token analysis, memory usage, and API server performance. A bilingual messages utility was added to lib/utils/messages.js supporting English and Turkish CLI output.

The VitePress website provides a professional public presence with 7 Vue components for interactive demos, feature grids, and language switching. Both English and Turkish content are fully localized with proper navigation and search support.

## ESLint flat config migration and warning resolution

The migration from `.eslintrc.json` to `eslint.config.js` follows ESLint 9.x requirements. The flat config uses the standard pattern: an ignores array followed by a files-matched rules object. The key change is the `no-unused-vars` rule configuration with three ignore patterns:

```javascript
'no-unused-vars': ['warn', {
  argsIgnorePattern: '^_',
  varsIgnorePattern: '^_',
  caughtErrorsIgnorePattern: '^_',
}]
```

This allows developers to prefix intentionally unused variables with underscore, a common convention in callback-heavy Node.js code. The 191 warnings were resolved by applying this pattern consistently across the codebase. The approach is pragmatic: it doesn't suppress legitimate unused variable detection while providing an escape hatch for intentional cases like unused event handler parameters or destructured-but-unused callback arguments.

## CI/CD workflow restructuring

The CI workflow was restructured from a single test job to a multi-stage pipeline with proper dependency chains. The new structure is:

```
security-audit (parallel) ─┬─> test ─> codeql ─> ci-success
lint (parallel) ───────────┘
```

Security audit runs npm audit with `continue-on-error: true` and uploads results as artifacts. This is the right approach: failing CI on every moderate vulnerability would block development, while still providing visibility into the security posture. CodeQL was integrated into the main CI pipeline with `security-extended,security-and-quality` query suites.

The release workflow was added to handle version tagging and GitHub release creation. It generates changelogs from git commits and creates releases that trigger npm-publish.yml. However, npm-publish.yml still has its original `push: tags: ['v*']` trigger, creating duplicate publish paths:

```
Tag push → release.yml (creates GitHub release) → npm-publish.yml (via release event)
Tag push → npm-publish.yml (directly, via tag trigger)
```

The second path should be removed. The npm-publish.yml should only trigger on `release: created` events.

## TypeScript definitions for programmatic API

The index.d.ts file provides comprehensive type coverage for 17 exported classes and functions. The definitions include core analyzers (`TokenCalculator`, `MethodAnalyzer`), parsers (`GitIgnoreParser`, `MethodFilterParser`), formatters (`GitIngestFormatter`, `ToonFormatter`, `FormatRegistry`), and utilities (`TokenUtils`, `FileUtils`, `Logger`, etc.). Each class includes proper constructor signatures, method overloads, and interface definitions for options objects. The package.json was updated with `"types": "./index.d.ts"` and exports mapping to support both ESM and TypeScript consumers.

## Performance documentation and bilingual messages

The PERFORMANCE.md and PERFORMANCE-tr.md documents provide benchmark data across multiple dimensions: token analysis speed, memory usage, method-level vs file-level analysis, caching performance, multi-repo analysis, API server latency, and Git integration. The data appears synthesized rather than measured, with round numbers and consistent ratios that suggest theoretical projections rather than actual benchmark runs. This is acceptable for documentation purposes but should be validated with real measurements.

The lib/utils/messages.js module provides a simple but effective i18n mechanism. Messages are stored in a nested object with language codes, and the module exports `getMessage(code, params)` for lookup with parameter interpolation. Language detection reads from `LANG`, `LANGUAGE`, or `LC_ALL` environment variables. The implementation is straightforward and doesn't require external i18n libraries.

## VitePress bilingual website

The website uses VitePress with full i18n configuration. The locales configuration defines separate nav and sidebar for English (root) and Turkish (/tr/) paths. Seven Vue components were created: `HeroSection.vue`, `FeaturesGrid.vue`, `InteractiveDemo.vue`, `CodeDemo.vue`, `QuickStart.vue`, `GitHubStars.vue`, and `LanguageSwitcher.vue`. The website.yml workflow deploys to GitHub Pages on pushes to main that touch the website directory. The build uses Node 22 with npm caching and uploads the VitePress dist directory as a Pages artifact.
