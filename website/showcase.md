# Showcase: ctxman on its own repository

Every number and output on this page comes from running ctxman on a clone of this repository at
commit `{{ data.meta.commit }}` ({{ data.meta.commitDate.slice(0, 10) }}), with exact tiktoken
counts. The script that does it,
[`website/scripts/build-showcase.mjs`](https://github.com/hakkisagdic/ctxman/blob/main/website/scripts/build-showcase.mjs),
drives the CLI, the MCP server and the REST API. Nothing on this page is edited by hand.

## 3. Keep only the source, and check the fit

`.contextinclude` turns the logic around: only what matches is analysed. `--target-model` checks the
result against the model's context window:

<Terminal title=".contextinclude" :output="ex.contextinclude.config" />
<Terminal title="~/ctxman" :command="ex.contextinclude.command" :output="ex.contextinclude.output" />

{{ ex.contextinclude.files }} files and {{ n(ex.contextinclude.tokens) }} tokens: the whole source of
ctxman fits in Claude Sonnet 4.5's 200K window, {{ data.stats.reduction }}% less than where we
started.

## 4. Same context, fewer tokens

`--context-export` writes the context as JSON by default; `-o toon` uses the official
[TOON](https://github.com/toon-format/toon) encoder instead. Token counts of the two exports:

| Context                                                     | JSON                             | TOON                             | Saving                           |
| ----------------------------------------------------------- | -------------------------------- | -------------------------------- | -------------------------------- |
| File list                                                   | {{ n(ex.formats.files.json) }}   | {{ n(ex.formats.files.toon) }}   | {{ ex.formats.files.saving }}%   |
| Method map (`-m`), {{ n(ex.formats.totalMethods) }} methods | {{ n(ex.formats.methods.json) }} | {{ n(ex.formats.methods.toon) }} | {{ ex.formats.methods.saving }}% |

TOON gains most on uniform lists, such as a method map where every row has a name, a line and a

## 8. Ask through MCP

`bin/mcp-server.js` speaks the Model Context Protocol over stdio, so Claude Desktop and other MCP
clients can call ctxman directly. In `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "ctxman": {
      "command": "node",
      "args": ["/usr/local/lib/node_modules/ctxman/bin/mcp-server.js"]
    }
  }
}
```

The path is `$(npm root -g)/ctxman/bin/mcp-server.js` on your machine. The server offers
{{ ex.mcp.tools.length }} tools — {{ ex.mcp.tools.join(', ') }} — plus file resources and prompts.
A `list_methods` call, as the client sends it and as ctxman answers:

<Terminal title="tools/call" :output="json(ex.mcp.request)" />
<Terminal title="result" :output="json(ex.mcp.response)" />

## 9. A hard token budget over REST

`ctxman serve` starts a local REST API. `POST /api/v1/context` with `targetTokens` fills the budget
with the highest-ranked files (core code first) and never goes over it:

## Regenerate this page

```bash
npm ci
node website/scripts/build-showcase.mjs
```

The script clones the repository into a temporary directory, runs every step above and writes
`website/.vitepress/data/showcase.json`, which this page and the home page read.
